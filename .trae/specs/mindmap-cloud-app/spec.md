# 定制化思维导图应用 - 产品需求文档 (PRD)

## Overview
- **Summary**: 基于开源项目 `simple-mind-map`（思绪思维导图），新建 Vue 3 前端（`myweb/`）并新增 Node.js 后端，构建具备本地文件、个人云端文档、团队云端文档（含实时协同编辑）、用户与团队管理、大模型生成思维导图能力的 BS 架构应用。
- **Purpose**: 在保留现有思维导图全部编辑能力的基础上，补齐后端服务、账户体系、云端文件、团队实时协同与 AI 生成能力，达到可上线的生产环境级别。
- **Target Users**: 个人用户（本地+云端个人文档）与团队用户（团队共享文档，支持多人实时协同编辑）。

## Goals
- 新建 Vue 3（Vite）前端 `myweb/`，完整移植并使用 `simple-mind-map` 核心库的全部编辑、导入、导出能力。
- 新增 Node.js + Express + better-sqlite3 后端，提供账户、团队、云端文件 API。
- 实现团队文档的多人实时协同编辑（基于 Yjs + WebSocket）。
- 头像与思维导图节点图片存储于服务器文件系统（非 base64 入库），通过静态 URL 引用。
- 实现本地文件 / 云端个人文件 / 团队文件三者之间的相互转换（另存为）。
- 集成大模型生成思维导图内容能力，支持配置 baseUrl、apiKey、model。
- 整体界面简洁现代、美观、易用，生产环境级别。

## Non-Goals
- 不实现付费/订阅/计费能力。
- 不实现移动端原生 App，仅保证桌面浏览器体验。
- 不重写核心思维导图渲染库（`simple-mind-map/` 保持不变）。
- 不实现复杂的组织架构/多级团队，仅单级团队。
- 不实现互联网公网部署与 HTTPS/SSL，仅局域网部署。

## Background & Context
- 仓库根目录为 `simple-mind-map` 开源项目。核心库在 `simple-mind-map/`（框架无关，可直接在 Vue 3 中使用）。
- 原 Web 应用在 `web/`（Vue 2 + ElementUI）。本次在 `myweb/` 新建 Vue 3 + Vite 前端，不修改 `web/`。
- 核心库 `Cooperate.js` 插件基于 Yjs，`setProvider(provider, config)` 支持传入自定义 provider（如 `y-websocket` 的 WebsocketProvider），可用于实时协同。
- 原 Web 应用已有 AI 生成功能（`web/src/utils/ai.js` + `web/scripts/ai.js` 代理），配置项含 api/key/model/port。本次直接集成到新前端，配置 baseUrl/apiKey/model。
- 运行环境 Windows，当前 Node v24.13.0 / npm 11.6.2；目标部署 Node 18 LTS，后端代码与依赖保持 Node 18 兼容。

## Functional Requirements

### FR-1 后端服务与账户体系
- **FR-1.1**: 提供 Node.js + Express + better-sqlite3 后端，监听端口（默认 3000），提供 RESTful JSON API 与 WebSocket（协同）。
- **FR-1.2**: 用户注册：用户名、邮箱、密码（bcrypt 哈希），返回 JWT。
- **FR-1.3**: 用户登录：用户名/邮箱 + 密码，返回 JWT。
- **FR-1.4**: JWT 鉴权中间件，受保护接口校验 `Authorization: Bearer <token>`。
- **FR-1.5**: 获取/更新当前用户信息（昵称、邮箱、头像 URL）。
- **FR-1.6**: 头像上传接口：`POST /api/user/avatar`，保存到服务器文件系统，返回 URL。

### FR-2 团队管理
- **FR-2.1**: 创建团队（名称、描述），创建者为 owner。
- **FR-2.2**: 列出我加入的所有团队。
- **FR-2.3**: 生成团队邀请码（6 位），凭码加入团队。
- **FR-2.4**: 列出团队成员（含角色），owner 可移除成员。
- **FR-2.5**: 退出团队（owner 需先转让或解散）。

### FR-3 云端文件管理
- **FR-3.1**: 个人文件 CRUD（创建、列表、详情、更新、删除）。
- **FR-3.2**: 团队文件 CRUD（归属团队，团队成员可见可编辑）。
- **FR-3.3**: 非团队成员禁止访问团队文件。
- **FR-3.4**: 思维导图节点图片上传接口：`POST /api/upload/image`，保存到服务器文件系统，返回可访问 URL，供节点引用。

### FR-4 实时协同编辑
- **FR-4.1**: 后端集成 `y-websocket` 服务，WebSocket 路径 `/ws`，按房间（文件 id）隔离。
- **FR-4.2**: 编辑团队文件时启用 `Cooperate` 协同插件，通过 `y-websocket` 连接后端。
- **FR-4.3**: 多人同时编辑同一团队文件时，实时同步节点变更与光标（感知）位置。
- **FR-4.4**: 协同数据定期（或最后一个人离开房间时）持久化到数据库。

### FR-5 大模型生成思维导图
- **FR-5.1**: 用户可配置大模型 baseUrl、apiKey、model（存于用户配置，支持用户级与全局默认）。
- **FR-5.2**: 提供"AI 生成思维导图"功能：输入主题，调用大模型生成思维导图 JSON 结构并渲染。
- **FR-5.3**: 提供"AI 续写/扩展节点"功能：对选中节点调用大模型生成子节点。
- **FR-5.4**: AI 请求通过后端代理转发（规避浏览器 CORS，且避免暴露配置），支持流式输出。

### FR-6 前端：登录与注册
- **FR-6.1**: `/login` 与 `/register` 页面，表单校验，登录成功后跳转工作台。
- **FR-6.2**: 未登录访问受保护路由自动跳转登录页。
- **FR-6.3**: 登出清除 token 与用户状态，回到登录页。

### FR-7 前端：文件管理工作台
- **FR-7.1**: `/dashboard` 页面，三标签页：本地文件 / 我的云文档 / 团队文档。
- **FR-7.2**: 本地文件：显示浏览器本地最近文件，支持新建空白图、打开本地 `.smm`、导入。
- **FR-7.3**: 我的云文档：拉取列表，支持新建、重命名、删除、打开编辑。
- **FR-7.4**: 团队文档：选择团队后显示该团队文件，支持新建/打开/删除；团队文件标注"可协同"。

### FR-8 前端：编辑页与文件保存/转换
- **FR-8.1**: `/edit` 编辑页保留核心库全部编辑、导入、导出能力。
- **FR-8.2**: 顶部显示当前文件名称与来源（本地/个人云/团队云）；团队文件显示在线成员。
- **FR-8.3**: 本地文件可"另存为"云端个人文件或团队文件。
- **FR-8.4**: 云端个人文件可"另存为"本地文件或团队文件。
- **FR-8.5**: 团队文件可"另存为"本地文件或个人云端文件。
- **FR-8.6**: 云端文件编辑后保存调用后端更新接口。
- **FR-8.7 实时自动保存（防数据丢失）**:
  - **本地文件**：编辑变更后防抖（约 1.5s）自动写入本地文件句柄（File System Access API）；同时在 localStorage 保留最近一份快照，若文件写入失败则以快照兜底，下次打开提示恢复。
  - **云端个人文件**：编辑变更后防抖（约 2s）自动调用 `PUT /api/files/:id` 保存；顶部显示"保存中/已保存/保存失败"状态；保存失败时保留本地快照并重试。
  - **团队文件**：通过 Yjs 协同实时同步到服务器内存，后端节流（约 3s）持久化到数据库；房间空时立即落库。
  - **页面关闭保护**：存在未保存变更时，`beforeunload` 弹出浏览器原生确认提示，防止误关。
  - 网络异常时云端文件变更暂存本地队列，网络恢复后自动重试保存。

### FR-9 前端：个人资料、团队管理与 AI 配置
- **FR-9.1**: `/profile`：修改昵称、邮箱、上传头像。
- **FR-9.2**: `/teams`：团队列表、创建团队、成员管理、邀请码。
- **FR-9.3**: AI 配置页面/弹窗：设置 baseUrl、apiKey、model，保存到用户配置。

### FR-10 界面风格与易用性
- **FR-10.1**: 登录/注册/工作台等新页面采用简洁现代风格（卡片、圆角、阴影、留白），配色统一。
- **FR-10.2**: 编辑页工具栏视觉与新页面风格协调。
- **FR-10.3**: 所有操作均有加载/成功/失败反馈。

## Non-Functional Requirements
- **NFR-1**: 后端使用 SQLite 嵌入式数据库，数据文件存于 `server/data/`。
- **NFR-2**: 密码 bcrypt 哈希；JWT 密钥通过环境变量配置。
- **NFR-3**: 头像与节点图片存于服务器文件系统（`server/uploads/avatars/`、`server/uploads/images/`），通过 `/static/` 静态路由访问，数据库仅存 URL。
- **NFR-4**: 云端文件 JSON 内容大小限制 20MB（节点图片走文件存储，JSON 通常远小于此），超出拒绝并提示。
- **NFR-5**: 前端生产构建（Vite build）与后端可同时启动；前端通过代理访问后端 API。
- **NFR-6**: 后端提供 CORS 支持；仅局域网部署，不强制 HTTPS。
- **NFR-7**: 关键 API 具备基本错误处理与参数校验。
- **NFR-8**: 界面在 Chrome/Edge 最新版下渲染正常。

## Constraints
- **Technical**: 新建 `myweb/` 使用 Vue 3 + Vite；后端 Node.js 18 LTS + Express + better-sqlite3 + y-websocket + ws。核心库 `simple-mind-map/` 不修改。后端依赖均选用兼容 Node 18 的版本（better-sqlite3 v11、Express v4 等）。
- **Business**: 单级团队模型；团队文件对所有成员可见可编辑并支持实时协同。
- **Deployment**: 仅局域网部署，HTTP 即可，不配置 SSL。

## Assumptions
- 用户接受本地开发运行前后端两个进程（前端 dev server + 后端）。
- 大模型接口兼容 OpenAI Chat Completions 格式（流式）。
- 团队协同通过后端 WebSocket 中转，局域网内可达。
- 生产/部署环境 Node 版本为 18 LTS，开发环境当前为 Node 24，代码需保持向下兼容 Node 18（不使用 Node 20+ 独有 API）。

## Acceptance Criteria

### AC-1: 后端账户注册与登录可用
- **Type**: `rule`
- **Given**: 后端服务已启动且数据库已初始化
- **When**: 调用 `POST /api/auth/register` 创建用户，再调用 `POST /api/auth/login`
- **Then**: 两次请求均返回 2xx 且包含 JWT；使用该 token 访问 `GET /api/user/profile` 返回当前用户信息
- **Pass Condition**: 注册→登录→带 token 获取 profile 三步链路成功
- **Evidence**: 接口测试日志或前端登录跳转成功

### AC-2: 团队创建与加入
- **Type**: `rule`
- **Given**: 用户 A 已登录
- **When**: A 创建团队并生成邀请码，用户 B 使用邀请码加入
- **Then**: B 的团队列表包含该团队；A 的成员列表包含 B
- **Pass Condition**: 两个用户均能在各自团队列表中看到该团队
- **Evidence**: 团队列表接口返回数据

### AC-3: 云端个人文件 CRUD
- **Type**: `rule`
- **Given**: 用户已登录
- **When**: 创建文件 → 列表查询 → 获取详情 → 更新内容 → 删除
- **Then**: 每一步返回成功且数据一致；删除后列表不再包含该文件
- **Pass Condition**: 完整 CRUD 链路数据一致
- **Evidence**: 接口调用返回

### AC-4: 团队文件访问控制
- **Type**: `rule`
- **Given**: 团队 T 有成员 A、B；用户 C 不在 T 中
- **When**: A 在 T 下创建文件；B 和 C 分别请求该团队文件列表
- **Then**: B 可见该文件，C 收到 403/404 且不可见
- **Pass Condition**: 非成员无法访问团队文件
- **Evidence**: B/C 调用列表接口的返回状态码

### AC-5: 团队文档实时协同编辑
- **Type**: `rule`
- **Given**: 团队 T 有成员 A、B，文件 F 属于 T
- **When**: A 打开 F 进入编辑，B 同时打开 F
- **Then**: A 修改节点后 B 端实时看到变更；B 选中节点时 A 端看到 B 的光标标识
- **Pass Condition**: 两端节点变更与感知位置实时同步
- **Evidence**: 双浏览器窗口操作录像/截图

### AC-6: 本地文件另存为云端个人文件
- **Type**: `rule`
- **Given**: 用户已在编辑页打开一个本地 `.smm` 文件
- **When**: 点击"另存为 → 我的云文档"，输入名称并确认
- **Then**: 后端创建对应个人云端文件；工作台"我的云文档"列表可见该文件
- **Pass Condition**: 转换后云端列表出现新文件且内容一致
- **Evidence**: 前端操作 + 后端列表接口返回

### AC-7: 云端文件保存与本地导出
- **Type**: `rule`
- **Given**: 用户已打开一个云端个人文件并编辑
- **When**: 点击"保存"，再点击"另存为 → 本地文件"
- **Then**: 保存接口返回成功且内容更新；浏览器下载 `.smm` 文件
- **Pass Condition**: 云端内容更新 + 本地文件下载成功
- **Evidence**: 保存接口返回 + 下载文件存在

### AC-7.1: 文档实时自动保存防丢失
- **Type**: `rule`
- **Given**: 用户正在编辑文档（本地或云端个人）
- **When**: 停止编辑超过防抖时间（本地 1.5s / 云端 2s），或直接关闭浏览器
- **Then**: 变更被自动持久化（本地写入文件 / 云端调用保存接口）；团队文件通过 Yjs 实时同步并由后端节流落库
- **Pass Condition**: 重新打开文档后内容为最后一次编辑状态，无丢失；顶部保存状态指示器正常显示
- **Evidence**: 编辑后关闭再打开内容一致 + 保存状态指示器截图/日志

### AC-8: 大模型生成思维导图
- **Type**: `rule`
- **Given**: 用户已配置 AI（baseUrl、apiKey、model）
- **When**: 在编辑页点击"AI 生成"，输入主题并确认
- **Then**: 后端代理调用大模型，返回思维导图结构并渲染为节点树
- **Pass Condition**: 画布出现 AI 生成的多级节点
- **Evidence**: 生成后端到端渲染截图 + 后端代理日志

### AC-9: 头像与节点图片文件存储
- **Type**: `rule`
- **Given**: 用户上传头像或在节点中插入图片
- **When**: 上传完成
- **Then**: 文件存于 `server/uploads/`，数据库仅存 URL，可通过 `/static/...` 访问
- **Pass Condition**: 数据库字段为 URL 路径而非 base64，图片可正常显示
- **Evidence**: 数据库记录 + 图片 URL 可访问

### AC-10: 前端路由与鉴权守卫
- **Type**: `rule`
- **Given**: 未登录状态
- **When**: 直接访问 `/dashboard`、`/edit`、`/teams`
- **Then**: 自动跳转至 `/login`；登录后可正常访问
- **Pass Condition**: 未登录受保护路由均跳转登录页
- **Evidence**: 浏览器地址栏跳转行为

### AC-11: 界面现代美观与一致性
- **Type**: `rubric`
- **Dimension**: 整体视觉风格的现代感与一致性
- **Scale**: 1-5
- **Anchors**: 1 = 原始朴素样式，无统一设计；3 = 基础卡片布局，但配色/间距不够统一；5 = 简洁现代，统一配色/圆角/阴影/留白，登录页与工作台视觉协调，达到生产级产品观感
- **Pass Threshold**: >= 4
- **Evidence**: 登录页、工作台、编辑页截图

### AC-12: 现有思维导图编辑能力完整保留
- **Type**: `rule`
- **Given**: 进入编辑页
- **When**: 进行节点增删改、切换结构/主题、导入 `.xmind`/`.md`、导出 `png`/`svg`/`pdf` 等操作
- **Then**: 全部正常可用，行为与原 Web 应用一致
- **Pass Condition**: 核心编辑与导入导出功能无回归
- **Evidence**: 手动操作验证记录

## Open Questions
- [ ] 协同数据持久化策略：实时落库 vs 最后离开房间时落库，默认采用"数据变更节流保存 + 房间空时保存"。
- [ ] AI 配置存储位置：默认存于用户表配置字段（用户级），同时支持环境变量配置全局默认值。
