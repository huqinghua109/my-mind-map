# my-mind-map 项目结构说明

本文档基于仓库当前实际代码整理，说明项目由哪些部分组成、各目录内部结构、一次典型请求的链路，以及编辑页中核心库、Vue 组件、协同与保存之间的关系。

> 核实时间：2026-11-08。技术标识（目录名、文件名、依赖名、脚本名）均取自仓库实际内容；少数无法从代码直接确认的点已在文末「不确定项」中标注。

---

## 1. 项目总览

仓库包含五个部分：

| 部分 | 目录 | 技术栈 | 职责 |
| --- | --- | --- | --- |
| 核心库 | `simple-mind-map/` | 原生 JS + SVG.js | 思维导图渲染内核：画布、节点、布局、主题、命令历史、插件体系、导入导出、协同插件 |
| 原版前端 | `web/` | Vue 2 + Vue CLI 4 + Element UI + Vuex 3 | 上游官方演示应用，同时承担核心库的构建工具链（`buildLibrary`） |
| 定制前端 | `myweb/` | Vue 3 + Vite 5 + Pinia + Element Plus | 本项目的实际前端：登录注册、工作台、团队、个人云/团队云/本地三种编辑来源、AI 能力 |
| 后端 | `server/` | Node.js (>=18) + Express + sql.js + y-websocket | 认证、用户、团队、文件、上传、AI 代理、协同 WebSocket 服务 |
| 根目录构建/部署文件 | `/`（`Dockerfile`、`nginx.conf`、`copy.js`、`index.html`、`dist/`） | — | 面向原版 `web` 的静态站点构建与容器化部署 |

相互关系：

```
simple-mind-map（核心库，源码直接被 myweb 引用）
        ▲                         ▲
        │ buildLibrary            │ alias 'simple-mind-map' -> ../simple-mind-map
        │                         │
      web（原版前端）            myweb（定制前端）──HTTP /api──▶ server ──▶ server/data/app.db
        │                         │
        │ build                   └──WebSocket /ws（协同）──▶ server/ws.js ──▶ 同一个 app.db
        ▼
  根目录 dist/ + index.html ──▶ 根目录 Dockerfile / nginx.conf（仅静态托管）
```

要点：

- `myweb` 通过 Vite 别名 `simple-mind-map` 直接引用 `../simple-mind-map` 源码（见 `myweb/vite.config.js`），不依赖 npm 上发布的同名包。
- 根目录的 `Dockerfile`、`nginx.conf` 只服务原版 `web` 的构建产物，**不包含** `/api` 与 `/ws` 转发，不能直接用于 `myweb + server` 的部署；定制部署的反代配置见离线部署包中的 `nginx/` 目录。
- `web` 的 `buildLibrary` 脚本把核心库打包到 `simple-mind-map/dist/`（浏览器 UMD 与 ESM 两种形式），这是核心库的分发产物，`myweb` 运行时不使用它。

## 3. `simple-mind-map/` 核心库

入口文件：

- `index.js`：`class MindMap` 主类。负责合并默认配置、预处理节点数据（根节点强制展开、补齐 `uid`）、创建 SVG 容器分组（连线 / 节点 / 关联线 / 其他）、初始化主题与缓存、按「preload 优先」顺序注册插件、实例化 `Event`/`KeyCommand`/`Command`/`Render`/`View`/`BatchExecution`，最后执行首次渲染并把初始数据写入历史栈。对外方法包括 `setData`、`updateData`、`getData`、`setLayout`、`setTheme`、`execCommand`、`export`、`destroy` 等。
- `full.js`：全量入口。导入 `index.js` 并注册全部插件（MiniMap、Watermark、KeyboardNavigation、ExportXMind、ExportPDF、Export、Drag、Select、AssociativeLine、RichText、TouchEvent、NodeImgAdjust、Search、Painter、Scrollbar、Formula、RainbowLines、Demonstrate、OuterFrame、MindMapLayoutPro、NodeBase64ImageStorage、**Cooperate**），同时挂载 `xmind`/`markdown` 解析器、图标列表、常量与默认主题，并声明 `MindMap.version = '0.14.0-fix.3'`。`myweb` 使用的正是这个入口。

`src/` 分层（均为实际存在的目录/文件）：

| 目录/文件 | 职责 |
| --- | --- |
| `constants/` | 常量、默认配置（`constant.js`、`defaultOptions.js`） |
| `core/` | 内核能力 |
| ├─ `core/command/` | 命令与快捷键（`Command.js`、`KeyCommand.js`） |
| ├─ `core/event/` | 事件总线 |
| ├─ `core/render/` | 渲染器（`Render.js`、`TextEdit.js`、`node/` 下的节点与样式实现） |
| └─ `core/view/` | 视图变换（缩放、平移、适配） |
| `layouts/` | 布局算法：`MindMap.js`、`LogicalStructure.js`、`CatalogOrganization.js`、`OrganizationStructure.js`、`Fishbone.js`（含 `fishboneUtils.js`）、`Timeline.js`、`VerticalTimeline.js`，公共基类 `Base.js` |
| `parse/` | 导入导出解析：`xmind.js`、`markdown.js`、`markdownTo.js`、`toMarkdown.js`、`toTxt.js` |
| `plugins/` | 插件实现，单文件插件（如 `RichText.js`、`Scrollbar.js`、`Cooperate.js`）与目录形式插件（`associativeLine/`、`outerFrame/`） |
| `svg/` | 内建 SVG 图标资源（如 `icons.js`） |
| `theme/` | 主题定义（`default.js`、`index.js`） |
| `utils/` | 通用工具：`index.js`、`AutoMove.js`、`BatchExecution.js`、`Lru.js`、`mersenneTwister.js`、`simulateCSSBackgroundInCanvas.js`、`xmind.js` |

核心库自身不访问网络、不持久化数据；数据读写完全交给使用方（原版 `web` 用它的接口，`myweb` 用 `api-adapter.js` + 后端接口）。

## 4. `web/` 原版前端

- 技术栈：Vue 2.6 + `@vue/cli-service` 4 + Element UI + Vuex 3 + vue-router 3，另有 `simple-mind-map` 与 `simple-mind-map-plugin-themes` 依赖。
- 脚本（`web/package.json`）：
  - `serve`：`vue-cli-service serve`
  - `build`：`vue-cli-service build && node ../copy.js`（产物写入根目录 `dist/`，入口页复制到根 `index.html`）
  - `buildLibrary`：把 `simple-mind-map/full.js` 打包到 `simple-mind-map/dist/`，并用 esbuild 额外产出 ESM / 压缩 ESM 版本
  - `ai:serve`：本地 AI 演示服务脚本
- 源码关键结构：`src/main.js`、`src/router.js`（`/` 与 `/edit` 路由）、`src/pages/`（含 `Edit/` 编辑器与 `Doc.vue`）、`src/api/`、`src/store.js`。

定位：上游参考实现 + 核心库打包工具。本项目实际对外服务的是 `myweb`，`web` 主要用于对照上游行为与生成核心库分发包。

## 5. `myweb/` 定制前端

技术栈：Vue 3 + Vite 5 + Pinia + Element Plus，`type: module`。脚本为 `dev`（`vite`）、`build`（`vite build`）、`preview`（`vite preview`）。构建产物为 `myweb/dist/`。

`src/` 结构：

| 路径 | 内容 |
| --- | --- |
| `main.js` / `App.vue` | 应用入口：注册 Pinia、Element Plus 与图标、全局 `$bus`、`$t`、`$i18n`，引入全局样式与图标字体 |
| `router/index.js` | 路由：`/`、`/login`、`/register`、`/dashboard`、`/edit`、`/profile`、`/teams`；`createWebHistory`；未登录访问受保护页会跳登录 |
| `layouts/MainLayout.vue` | 顶部导航（工作台 / 团队）与用户菜单（个人资料、AI 配置、退出登录） |
| `pages/` | 页面：`Login.vue`、`Register.vue`、`Dashboard.vue`、`Edit.vue`、`Profile.vue`、`Teams.vue` |
| `api/request.js` | axios 实例：`baseURL: '/api'`，超时 30 秒；请求自动带 `Bearer` token；响应统一解包 `code`；401 清除 token 并跳 `/login` |
| `api/index.js` | 接口封装：auth、user、teams、files、upload、ai（AI 聊天为流式响应） |
| `store/user.js` | Pinia 用户 store：token、userInfo 存 localStorage，登录/注册/登出 |
| `mindmap/` | 编辑器与组件层（见下） |
| `style/`、`utils/` | 全局样式与页面级工具函数 |
| `shims/`（位于 `mindmap/` 下） | 兼容层与第三方库轻量替身 |

`mindmap/` 内部：

| 路径 | 内容 |
| --- | --- |
| `MindMapEditor.vue` | 核心库的 Vue 封装：`new MindMap(...)`、管理容器尺寸、转发核心库事件到 `$bus`、`Control+S` 触发 `save` 事件、`loadPlugins()`、`ready` 事件抛出实例 |
| `components/` | 约 39 个编辑器 UI 组件，按功能分组：工具栏按钮（`ToolbarNodeBtnList`）、侧边栏（`OutlineSidebar`、`Style`、`Theme`、`Structure`、`Setting`、`Search`、`NodeIconSidebar` 等）、节点元素（`NodeNote`、`NodeImage`、`NodeIcon`、`NodeHyperlink`、`NodeTag`、`NodeOuterFrame`）、辅助（`Contextmenu`、`ShortcutKey`、`RichTextToolbar`、`Navigator`、`Scrollbar`、`Count`、`Demonstrate`）等 |
| `store.js` | 编辑器 Pinia store，并提供 Vuex 风格的 `mapState`/`mapMutations` 兼容垫片；编辑器本地配置持久化到 localStorage（键 `myweb_editor_config`） |
| `api-adapter.js` | 原版编辑器组件所依赖的「本地持久化接口」改为 localStorage 实现；只保存视图与配置，思维导图数据由 `Edit.vue` 的自动保存负责 |
| `bus.js` / `element-compat.js` / `i18n.js` | 事件总线、Element UI → Element Plus 兼容、国际化 |

`pages/Edit.vue` 的三种编辑来源（`route.query.source`）：

- `local`：本地文件，浏览器内保存，走 File System Access API（支持时）与 localStorage 快照
- `personal`：个人云文件，`files.detail(fileId)` 读取，编辑后 `files.update(fileId, content)` 写入
- `team`：团队云文件，读取同上，但**前端不负责保存**，改动通过协同 WebSocket 同步，由服务端落库

## 6. `server/` 后端

运行入口 `index.js`：Express 应用，默认 `PORT=3000`，启用 CORS 与 20MB 的 JSON/表单解析；`/static` 静态托管上传文件；挂载 `/api/auth`、`/api/user`、`/api/teams`、`/api/files`、`/api/upload`、`/api/ai`、`/api/health`；启动时创建上传目录，等待 `db.ready` 后创建 HTTP 服务并挂载 WebSocket。

| 文件/目录 | 职责 |
| --- | --- |
| `index.js` | HTTP 服务入口、中间件与路由装配、静态目录、健康检查 |
| `db.js` | sql.js（WASM SQLite）封装：数据文件 `data/app.db`，启动时加载到内存；写操作标记 dirty，约 300ms 防抖后落盘；建表语句在此 |
| `ws.js` | 协同服务：`WebSocketServer({ noServer: true })`，仅接受 `/ws` 与 `/ws/...` 升级；房间名取自路径；识别 `file-<id>` 房间；监听 Yjs 文档变化，约 3 秒防抖后把扁平 Y.Map 还原为 `{root: ...}` 并 `UPDATE files SET content=?...` |
| `middleware/auth.js` | JWT 签发与校验；校验通过写入 `req.user` |
| `middleware/error.js` | 统一错误处理 |
| `routes/auth.js` | `POST /register`、`POST /login`、`GET /me`；密码 bcrypt 哈希，token 有效期 7 天 |
| `routes/files.js` | 个人文件与团队文件：`POST /personal`、`GET /personal`、`GET /:id`、`PUT /:id`、`DELETE /:id`；含个人归属与团队成员权限判断 |
| `routes/teams.js` | 团队创建/查询、成员、邀请码、加入/退出/移除成员、团队文件创建与列表 |
| `routes/upload.js` | 图片上传（multer 磁盘存储到 `uploads/images`，10MB，图片类型），返回 `/static/images/<filename>` |
| `routes/user.js` | 个人资料读写、头像上传（`uploads/avatars`，2MB），返回 `/static/avatars/<filename>` |
| `routes/ai.js` | AI 配置读写（用户级配置 `user_configs`，可回退到系统环境变量）；`POST /chat` 拼接兼容 OpenAI 的 `chat/completions` 并流式转发 |

数据库表（`db.js` 中 `CREATE TABLE IF NOT EXISTS`）：

- `users`：`id`、`username`（唯一）、`email`（唯一）、`password_hash`、`nickname`、`avatar`、时间戳
- `teams`：`id`、`name`、`description`、`owner_id`、`created_at`
- `team_members`：`(team_id, user_id)` 联合主键、`role`（默认 `member`）、`joined_at`
- `invitations`：`id`、`team_id`、`code`（唯一）、`created_by`、`created_at`
- `files`：`id`、`name`、`type`（`personal` / `team`）、`owner_type`（`user` / `team`）、`owner_id`、`created_by`、`content`、时间戳
- `user_configs`：`user_id` 主键、`ai_base_url`、`ai_api_key`、`ai_model`、`updated_at`

数据存储位置：

- 数据库文件：`server/data/app.db`（运行后自动创建）
- 上传文件：`server/uploads/images/`、`server/uploads/avatars/`
- 这两处是**运行时数据**，升级/迁移时必须单独备份，不能随代码覆盖

## 7. 典型请求链路

以「打开个人云文件并编辑保存」为例：

```
浏览器 myweb
  │ axios baseURL '/api'，携带 Authorization: Bearer <JWT>
  ▼
反向代理 nginx（/api 转发到 server:3000；/static 转发上传文件）
  ▼
server/index.js
  ├─ middleware/auth.js 校验 JWT → req.user
  ├─ routes/files.js   权限判断
  ▼
db.js（sql.js，内存 SQLite）
  ├─ 读：SELECT ... 返回文件 content
  └─ 写：UPDATE ... → markDirty → 约 300ms 防抖 → 写入 data/app.db
  ▼
浏览器拿到 { root: ... } 思维导图数据 → myweb 交给核心库渲染
```

协同链路（团队文件）：

```
浏览器 Edit.vue
  │ new WebsocketProvider(同源 '/ws', 'file-<fileId>', cooperate.getDoc())
  ▼
nginx /ws（Upgrade + Connection 头转发，长连接）
  ▼
server/ws.js
  ├─ y-websocket 维护房间共享文档
  ├─ 监听 Y.Map 变化 → 约 3 秒防抖
  └─ file-<id> 房间 → UPDATE files.content → db.js 落盘
```

上传链路：`POST /api/upload/image` → multer 写入 `uploads/images` → 返回 `/static/images/<file>` → nginx `/static` 直接回源或由 Express 静态托管。

## 8. 编辑页：核心库、Vue 组件、协同、保存的关系

1. **核心库实例**由 `MindMapEditor.vue` 创建（`new MindMap({ el, data, layout, theme, readonly, ... })`，入口为 `simple-mind-map/full`）。它只负责渲染与交互，不知道后端存在。
2. **Vue 组件层**（`mindmap/components/`）通过 `$bus` 与实例通信：组件发出 `execCommand` 等事件，`MindMapEditor.vue` 转发给核心库；核心库的 `node_active`、`data_change`、`node_tree_render_end` 等事件再转发回 `$bus`，供各面板刷新。
3. **编辑页 `Edit.vue`** 在 `ready` 事件拿到实例后：
   - 监听 `data_change` → `markUnsaved()` → `scheduleSave()`（本地 1500ms、云端 2000ms 防抖）
   - `local`：写入 localStorage 快照（`mindmap_open_<key>`、`mindmap_snapshot_<key>`），并在支持时写回本地文件句柄
   - `personal`：调用 `files.update(fileId, { content })`，成功后清除本地待提交草稿 `mindmap_pending_<fileId>`
   - `team`：**不调用保存接口**；`node_tree_render_end` 后调用 `cooperate.onDataChange(instance.getData())` 把本地数据灌入协同文档，之后由 `WebsocketProvider` 同步，服务端 `ws.js` 负责落库
4. **协同连接**：团队来源下创建 `WebsocketProvider(wsUrl, 'file-' + fileId, cooperate.getDoc())`，`wsUrl` 为同源 `ws(s)://<当前 host>/ws`（开发环境由 Vite 代理、生产由 nginx 转发），并设置用户信息与在线人数（awareness）。
5. **离开页面**：`beforeunload` / `pagehide` / 页面隐藏时触发一次立即保存；组件卸载时销毁 `WebsocketProvider` 与核心库实例。
